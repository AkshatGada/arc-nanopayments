Live compatibility issue found and fixed
- The initial seller challenge omitted resource.mimeType because the generic
  x402-rs type treats it as optional. Circle rejected the request with HTTP 400:
  "Invalid request: paymentPayload.resource.mimeType: Required".
- Nonce search and balances showed no admission or debit for that attempt.
- The example now explicitly sets application/json. The challenge regression
  test failed before this change and passes afterward.
- During diagnosis the initial authorization aged below the required remaining
  seven-day validity window; /verify explicitly rejected it as too short.
- After another empty nonce search and unchanged 0.1 balance, one fresh
  authorization for the same 0.001-test-USDC logical purchase was created.
- /verify returned isValid:true before the successful request. No ambiguous
  paid call was automatically retried; exactly one purchase has been charged.
