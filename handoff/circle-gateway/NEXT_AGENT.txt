WHAT WAS BUILT
The user selected recommendation #1: a native Rust/Axum Circle Gateway seller
using existing x402-rs middleware, with compatibility fixtures and tests.
No new SDK, buyer implementation or upstream crate modifications were made.
x402-axum and x402-types are pinned to upstream Git revision
e75adda8a0e3cf23db446883ba91b88bbab2fe28.

src/config.rs:
- Required nonzero EVM seller receive address; integer pricing 1..1,000,000
  atomic USDC, default 1000 (0.001 USDC).
- Arc Testnet eip155:5042002 default; Base Sepolia eip155:84532 also allowed.
- Pinned known USDC assets and testnet GatewayWallet:
  0x0077777d7EBA4688BDeF3E311b846F25870A19B9.
- Facilitator is Circle testnet HTTPS or numeric-loopback HTTP for mocks.
  No mainnet fallback; bounded timeout; validated public origin.

src/transport.rs:
- Private Gateway-specific reqwest client; redirects and automatic retries
  disabled. Only HTTP 200 is accepted before JSON parsing for all operations.
- Startup /supported is mandatory; supported capabilities are pinned for the
  lifetime of the process. Error bodies and redirect locations are redacted.

src/lib.rs:
- Existing x402-axum paygate, raw V2 PriceTag preserving full Gateway extra,
  settle_before_execution, correct GatewayWalletBatched signing metadata.
- Explicit resource.mimeType application/json, required by Circle's live API.
- GET /quote returns content after accepted payment; no separate /verify
  round trip in the seller's paid flow. Receipt must have matching network,
  valid matching payer and transfer UUID. The body says accepted/transferId.
- HEAD/POST/OPTIONS rejected before payment handling (including signed HEAD).
- All responses no-store. Bare settlement-error 402 becomes redacted 502 with
  automaticRetry:false and no fresh payment challenge.
- /health distinguishes loopback_mock from circle_testnet.

There is no durable purchase ledger, response recovery, reconciliation worker
or exactly-once guarantee. Timeout is an unknown outcome, not proof of failure.
A fresh authorization can charge a logical purchase again. EOA buyer support
only; no Nanopayments ERC1271 or Solana support is established.

INDEPENDENT AUDIT AND FIXES
The user requested a second agent audit, fixes for both bugs, regression tests,
and another audit by the same reviewer. Those steps were completed locally.
Original findings, both P2:
1. Generic HTTP transport followed a cross-origin 307 and forwarded the full
   payment payload beyond the initially allowlisted origin.
2. Generic facilitator parsing accepted success-shaped HTTP 400/412 bodies,
   allowing content fulfillment from an unsuccessful HTTP response.
Both were fixed in the local strict transport. Three added regression tests
failed against the old implementation and passed after the fixes. Tests cover
301/302/303/307/308 redirects for discovery/settlement with zero destination
requests, and success-shaped 400/412/201/202/other non-200 bodies with zero
fulfillment. The original audit probes now assert fixed behavior and pass.
The same agent re-audited and found no further concrete regression. It ran
the actual package checks and an independent harness. AUDIT.txt and
reproductions.log are pre-fix history; FIX_REAUDIT.txt is the later result.
That independent re-audit preceded the subsequent one-line MIME fix. Do not
claim the reviewer independently audited that later change. Its regression
and the successful real testnet flow provide separate validation.
